# Ravenswood · Trouble Brewing

A multiplayer, server-authoritative Blood on the Clocktower table for 5–15 human players. The host picks Trouble Brewing (22 characters) or Bad Moon Rising (25 characters) in the lobby. All characters are supported, with a rules-based automatic Storyteller and postgame decision audit. No API key or external model is required.

Create a room, copy the invitation, and have friends join from separate devices/browser profiles. Start with 5–15 players. Read the private journal at night; use public chat, whispers and private group chats by day. The host also plays and cannot inspect other players' roles. The host can remove players in the lobby (they may rejoin with the code). Any player can ask the table to end a game early, either by revealing every character or by going back to the lobby; a majority of the players who are online must agree within a minute. Either way nobody wins and the game is not recorded. Characters are dealt again at the next start. Anyone with the code can watch as a spectator, even mid-game: spectators see only public information, cannot chat or vote, and can take a seat in the lobby.

At night each player has 30 seconds from when their prompt reaches their screen; when time runs out, or the player is offline, the Storyteller chooses for them (doing nothing where the rules allow it, otherwise a random legal target, never the Demon itself). Dawn always comes 5–15 seconds after the last choice, so the length of a night reveals nothing. When a game ends, a game log shows every night choice, what the Storyteller told each player and its own decisions, but never whispers. Pages get a server-sent event whenever their room changes and fetch at once; polling every 1.8 seconds remains as the backstop and drives the timers. Use the same browser to recover your seat. A lost session cookie cannot be recovered by knowing a player's name.

See `docs/RULES-RESEARCH.md` and `docs/CHARACTERS.md` for sources, rules, balancing policy, and digital conventions. This is an unofficial implementation, not affiliated with The Pandemonium Institute. Character descriptions are paraphrased, with links to the official wiki. The icons in `public/botc/icons/` are official art from that wiki, resized to 256 px, and belong to The Pandemonium Institute.

## Development

The game is served at `/botc/` by the parent site. From the repository root, `npm run dev` starts the local site and `npm run build` builds it, using `botc/index.html` as the page entry. `npm run test:botc` runs rules tests. With a server running, `TEST_ORIGIN=<origin> node ravenswood/tests/api-smoke.mjs` exercises seven independent player sessions.

`server.mjs` is the API. Rooms are held in server memory, expire after six idle hours, and do not survive a restart. A private HttpOnly SameSite cookie identifies each browser's player seat; serializers omit hidden state and filter whispers. No game state is trusted from clients. Timers progress on incoming polling requests. Rooms are not publicly listed. Room codes admit players only before game start.

Accounts are optional and live in `lib/accounts.mjs`, in a `botc_accounts` table separate from the quota tracker's users. A logged-in player's cookie holds their account's session, so seats follow the account between devices. Without `DATABASE_URL` the login option is hidden and everyone plays as a guest. There is no email, so a forgotten password has to be reset in the database.

The leaderboard lives in `lib/leaderboard.mjs`. When a game ends, the server saves it to `botc_games` and `botc_game_players`, with one row per logged-in player, but only if at least three players at the table are logged in, so one person cannot farm wins with several browser profiles. Guests are left out. A game the table votes to end early is never saved. Wins follow the player's team at the end of the game, so a Goon who turned evil wins with evil. The Players list shows everyone with a recorded game A–Z, with the number of games played and no results or ranking, so nobody is compared by win rate. Each name opens a profile showing the player's record by team and mode, their most-played characters and recent games. During a game, players can open a profile from a seat's menu or a chat picture. In the lobby, or after a game ends, clicking a seat opens it.

Games that count also earn points: +5 for finishing, +25 for a win, +10 more for a Demon win, and +15 for your first win each day (the day resets at midnight UTC). Points are spent in the shop (`lib/shop.mjs`) on frames, name colours and titles, listed in `lib/cosmetics.mjs`. Points can also go into mystery chests (250 points for a random decoration from everything for sale plus a few chest-only items, with published tier odds of 55/30/11/4%; a duplicate refunds 100), be gifted (10–100 at a time, at most 100 a day, only to someone the sender has played a recorded game with, and only once the sender has 5 recorded games), or be bet by logged-in spectators on which team wins the game they are watching (10–100, closes when Day 2 begins, pays double if right, and only pays out if the game is recorded; otherwise the stake is returned). Players never bet. Chests, gifts and settled bets are rows in `botc_ledger`; an open bet is only held in server memory, so a restart voids it. No real money is involved anywhere. Pricier items look better. Some items can't be bought and unlock through play, such as winning 10 games as the Demon. Purchases are stored in `botc_items` and the equipped look on `botc_accounts.look`. A decoration changed during a game only shows from the next game, so a change can't be used as a signal while chat is closed at night. Decorations never depend on a player's character or team.

Limitations: no integrated voice/video, no bots replacing players, and no moderation console beyond the host's kick and hide-picture controls. Balancing is heuristic, not conversational AI. Public votes use a timed hand-lock adaptation. Browser QA and human group playtesting remain outstanding.
